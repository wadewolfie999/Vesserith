# 0.1.0 — first local orientation loop

Status: implementation authorized by the user on 2026-09-07.
Baseline: clean main at 3231d3c. Branch: codex/0.1.0-orientation.

## Problem and authorized scope

Fragmented sessions lose objectives, reasons, evidence locations, and the distinction
between possible and committed actions. Build one local orientation screen that can
be understood in about one minute, with durable state, explicit uncertainty,
activity history, context export, app versioning, and recoverable local iteration.
The complete initial personal context is held only in ignored local storage.

## Design decisions

A single versioned JSON orientation snapshot in SQLite is sufficient for one user
and at most 500 entries. SQL owns durability and append-only history; Python owns
validation. Compared with separately normalized objective/action/decision tables,
this keeps atomic saves and exports simple without a speculative relational model.
It trades fine-grained query efficiency for a small, explicit contract. The supported
bound is 500 entries and 2 MiB per request. Revisit when actual use exceeds this.

Retain one React screen; replace vinext/Cloudflare runtime wiring with Vite and
Flask. Existing declared frontend package versions remain locked; dependency pruning
is deferred, but old scripts/routes/publication workflow are removed. Dormant Sites
metadata does not enable hosting. No public asset directory is bundled.

App state and history commit in one transaction with optimistic revision checks.
Review dates do not activate work. Only one chosen action is allowed, with an action
and stopping point. Saving context is distinct from authorization to execute it.

## Exclusions

No hosting, accounts, multi-user operation, worldmap, general opportunity scoring,
external execution, attachments, machine searches, trading campaigns, sync, automatic
AI conversation capture, or system configuration. No Git remote push is implied.
