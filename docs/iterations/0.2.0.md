# 0.2.0 — orientation maps and visual reset

Status: implementation requested through browser feedback on 2026-09-07.
Baseline: tagged `v0.1.0` at `2e25cfc`. Branch: `codex/0.2.0-worldmaps`.

## Problem

The first screen looked like a form and made “Now” feel like a generic heading.
History and change controls only appended long panels below the fold. The user
needs an orientation surface that behaves like a map: choose a world, enter it,
inspect a signal, then edit only when needed.

## Authorized scope

- Rename the opening concept to `Your NOW`.
- Add two real entry points: Thesis Worldmap and Mynyra Worldmap.
- Make map cards and plotted signals interactive and keyboard accessible.
- Give History and What changed dedicated views with explicit back navigation.
- Replace always-visible objective inputs with readable context and an on-demand editor.
- Apply a deliberate visual system suitable for a personal orientation instrument.

## Exclusions

No new database fields, migrations, automatic prioritization, external execution,
worldmap synchronization, or changes to the existing uncertainty semantics.

## Acceptance checks

- Opening the app clearly presents `Your NOW` and the two worldmaps.
- Clicking either worldmap changes the main view and shows its signals.
- Clicking a signal selects it and exposes its uncertainty, possible action, and stopping point.
- History and What changed replace the main view and provide a clear return path.
- Objective editing is available without forcing text boxes into the first viewport.
- Existing persistence and recovery tests remain passing; build and lint remain clean.

## Verification results — 2026-09-07

- TypeScript production build and frontend lint passed.
- All 16 backend persistence and recovery tests passed.
- In-app browser verification confirmed the `Your NOW` screen, Thesis Worldmap
  trigger, Mynyra Worldmap trigger, signal selection inspector, on-demand editor,
  dedicated History view, dedicated What changed view, and return-to-NOW controls.
- No schema change or migration was required. The local database remains schema 1.
